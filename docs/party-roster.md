# รายชื่อผู้ร่วมงานรายคน (สูงสุด 10 ท่าน)

รองรับการ์ดแบบ **Custom** ที่หลังบ้านกำหนดจำนวนที่นั่งให้แขกแต่ละคน — แขกกดเลือกจำนวน
แล้วฟอร์มขึ้นช่องกรอกชื่อครบทุกท่าน พร้อมช่องแพ้อาหาร/ไม่ทาน ของแต่ละคนแยกกัน

> **⚠️ ไฟล์ `index.html` ถูกเจนจากหลังบ้าน** — โค้ดในเอกสารนี้ถูกแปะลงไฟล์ที่ deploy อยู่แล้ว
> เพื่อให้ใช้งานได้ทันที แต่จะ**หายเมื่อกด "อัปเดตการ์ดจากหลังบ้าน" ครั้งถัดไป**
> ต้องย้ายเข้า renderer ตาม [§3](#3-สิ่งที่ต้องแก้ในตัว-renderer) ถึงจะถาวร

---

## 1. พฤติกรรมที่ได้

| จำนวนที่นั่งที่เชิญ | หน้าตาฟอร์ม |
|---|---|
| 1 | ซ่อนคำถามจำนวนทั้งช่อง · การ์ดรายชื่อ 1 ใบ (ตัวเอง) + ช่องแพ้อาหาร |
| 2 | ปุ่มยาวแบบเดิม "มา 1 ท่าน / มา 2 ท่าน" |
| 3–10 | ชิปตัวเลขกริด 5 คอลัมน์ |

- ค่าเริ่มต้นค้างที่ **1 เสมอ** — จำนวนที่เชิญคือเพดานสิทธิ์ ไม่ใช่คำตอบล่วงหน้า
- กดเลข `k` → ขึ้นการ์ด `k` ใบ ใบละ 1 ท่าน
- **ท่านที่ 1 = ผู้ตอบรับ** ดึงชื่อจากช่อง "ชื่อผู้ร่วมงาน" ด้านบนอัตโนมัติ ไม่ต้องพิมพ์ซ้ำ
  (ยังมีช่องแพ้อาหารของตัวเอง)
- ท่านที่ 2 ขึ้นไป มีช่อง **ชื่อ-นามสกุล** + **แพ้อาหาร/ไม่ทาน**
- สลับจำนวนไปกลับ ค่าที่พิมพ์ไว้ไม่หาย
- กดส่งโดยชื่อไม่ครบ → ไม่ยิงขึ้นชีต เตือน แล้วเลื่อนไปช่องที่ว่าง
- การ์ดยืนยันหลังส่ง โชว์รายชื่อทั้งคณะให้ทวนก่อนปิดหน้า

เพดานตายตัวที่ **10** (`PARTY_MAX`) — หลังบ้านส่งค่ามากกว่านี้จะถูกตัดเหลือ 10

### เพดานมาจากไหน (เรียงตามลำดับความสำคัญ)

1. `PRESEATS` — จำนวนที่นั่งของแขกคนนั้น จาก `?n=` ในลิงก์ หรือ `seats` ที่ `/api/ginfo` ตอบกลับ
2. `CFG.maxSeats` — ค่ากลางของการ์ด (จาก `card.json` → `rsvp.props.maxSeats`, ตอนนี้ตั้งไว้ 10)
3. จำนวนปุ่มที่ renderer เรนเดอร์มาให้ (ใช้เมื่อไม่มีทั้ง 2 ข้อบน)

ตอนนี้ `CFG.maxSeats = 10` ถูกใส่ไว้ในไฟล์ที่ deploy แล้ว (ค่าเดียวกับ `card.json`) —
ลิงก์ทั่วไปจึงเลือกได้ถึง 10 ท่าน ส่วนลิงก์ที่มีรหัสแขกยังถูกจำกัดตามที่เชิญจริงเสมอ
(เชิญ 2 → เห็น 2 ปุ่ม, เชิญ 1 → ซ่อนคำถามจำนวนไปเลย)

ข้อดีอีกอย่างคือ**กันเหนียวกรณี ginfo หลับ** — ถ้า `/api/ginfo` ไม่ตอบ แขกที่เชิญไว้ 10 ท่าน
ก็ยังเลือกได้ถึง 10 แทนที่จะร่วงไปเหลือ 2

## 2. Payload ที่ยิงขึ้นชีต

เพิ่ม 2 ฟิลด์ใหม่ **แบบไม่ทำลายของเดิม** — Apps Script ตัวปัจจุบันมองข้ามคีย์ที่ไม่รู้จักได้เลย
ไม่ต้องแก้อะไรก็ยังทำงานเหมือนเดิม

```jsonc
{
  "cardId": "lertnalid-pinyapat",
  "name": "สมชาย ใจดี และ สมหญิง รักดี และ ก้อง ดีงาม",  // รวมทุกชื่อ — คอลัมน์เดิมอ่านได้
  "going": "yes",
  "seats": "3",
  "food": "",
  "diet": "สมชาย ใจดี: แพ้กุ้ง · ก้อง ดีงาม: มังสวิรัติ",   // ผูกชื่อกับอาหารแล้ว
  "msg": "ยินดีด้วยนะ",
  "note": "งด/แพ้: … · ยินดีด้วยนะ",
  "code": "SL-3VGCB",
  "at": "2026-08-27T14:13:29.399Z",

  // ── ใหม่ ──
  "guests": [
    { "n": "สมชาย ใจดี",   "d": "แพ้กุ้ง" },
    { "n": "สมหญิง รักดี", "d": "" },
    { "n": "ก้อง ดีงาม",   "d": "มังสวิรัติ" }
  ],
  "guestsText": "1. สมชาย ใจดี (แพ้กุ้ง)\n2. สมหญิง รักดี\n3. ก้อง ดีงาม (มังสวิรัติ)"
}
```

`guests` = โครงสร้างไว้ประมวลผล · `guestsText` = ข้อความพร้อมโชว์ ยัดลงเซลล์เดียวได้
10 ท่านยาวไม่ถึง 1 KB — ไม่ชนเพดาน `keepalive` 64 KB และไม่ชนเพดานเซลล์ Google Sheets (50,000 ตัวอักษร)

## 3. สิ่งที่ต้องแก้ในตัว renderer

repo ของ renderer ไม่ได้อยู่ใน GitHub org นี้ (มีแค่ `igen` = ระบบ project timeline
กับ `sl-ecard-data` = ข้อมูลการ์ด) — ตัวเรนเดอร์อยู่บน `admin-production-ce9d.up.railway.app`
ต้องเอาโค้ดไปแปะเอง 4 จุด

### 3.1 ฉีด `maxSeats` เข้า CFG

```diff
  var CFG = {
    "rsvpMode": "sheet",
+   "maxSeats": <rsvp.props.maxSeats ?? 2>,
    …
  };
```

มีอยู่ใน `card.json` แล้ว (`sections[rsvp].props.maxSeats = 10`) แค่ยังไม่ได้ส่งออกมา

ตอนนี้ค่า `10` ถูกเขียนตายตัวไว้ในไฟล์ที่ deploy แล้ว — พอ renderer อ่าน `card.json` เองได้
ก็เอาค่าจริงมาแทน จะได้ไม่ต้องแก้มือทุกครั้งที่เปลี่ยน `maxSeats`

### 3.2 markup ในฟอร์ม RSVP

```diff
- <div id="g2wrap" hidden>…ชื่อผู้ติดตาม…</div>
+ <div id="partyWrap" class="party" hidden></div>

- <div><label for="gdiet">อาหารที่ไม่ทาน…</label><input id="gdiet" …></div>
+ <div id="dietWrap"><label for="gdiet">อาหารที่ไม่ทาน…</label><input id="gdiet" …></div>
```

`#g2wrap` (ช่องผู้ติดตามเดี่ยว) และ `#dietWrap` (ช่องแพ้อาหารรวม) ถูกแทนที่ด้วยการ์ดรายคน
โค้ดจะซ่อนให้เองถ้ายังเรนเดอร์มา — ลบทิ้งได้เลยเมื่อย้ายเข้า renderer แล้ว

ปุ่ม `.seg-cnt` เรนเดอร์มากี่ปุ่มก็ได้ โค้ดสร้างใหม่ตามเพดานจริงอยู่แล้ว

### 3.3 CSS

ก๊อปจาก `index.html` — บล็อกที่ต่อท้ายกฎ `.form-warn{…}`
(`.seg-cnt.grid`, `.party`, `.party-row`, `.pr-hd`, `.pr-me`, `.done-party`)

### 3.4 JS

ก๊อป 3 ส่วนจาก runtime ใน `index.html`

| ส่วน | ตำแหน่งเดิม |
|---|---|
| `PARTY_MAX` / `seatCap()` / `partySize()` / `buildSeatChips()` / `renderParty()` / `mirrorHost()` / `applySeatsForm()` | แทนบล็อกเดิมตั้งแต่ `needG2()` ถึง `segBind('.seg-cnt', …)` |
| `party()` + `data()` | แทน `data()` เดิม |
| ตรวจชื่อครบก่อนส่ง | แทนเช็ค `needG2() && !val('gname2')` ใน submit handler |

`needG2()` ถูกลบทิ้งทั้งหมด — ไม่มีที่ไหนเรียกแล้ว

## 4. สิ่งที่ต้องแก้ใน Apps Script (ชีต)

**ไม่แก้ก็ใช้งานได้** — ชื่อทุกคนไปรวมอยู่ในคอลัมน์ `name` และอาหารอยู่ใน `diet` เหมือนเดิม
แต่ถ้าอยากได้รายคนแยกช่อง (จัดโต๊ะ/สรุปครัวง่ายกว่า) ให้เพิ่ม 2 คอลัมน์

### 4.1 เพิ่มคอลัมน์ในชีต

`guests` (JSON) และ `guestsText` (ข้อความหลายบรรทัด)

### 4.2 `doPost` — ตอนเขียนแถว

```js
// d = JSON.parse(e.postData.contents)
row[COL.guests]     = JSON.stringify(d.guests || []);
row[COL.guestsText] = d.guestsText || '';
```

### 4.3 `action=list` / `action=seat` — ตอนอ่านออกไป

ส่ง `guestsText` (และ `guests` ถ้าจะใช้) กลับไปด้วย

```js
return { …เดิม…,
  guestsText: r[COL.guestsText] || '',
  guests:     r[COL.guests]     || '' };
```

`checkin.html` และ `table.html` รับได้ทั้ง 3 รูปแบบแล้ว — ข้อความ, array, หรือ JSON string
ถ้าชีตยังไม่ส่งมา หน้าตาก็เหมือนเดิมทุกอย่าง

### 4.4 เช็คว่ามีเพดาน `seats` ค้างอยู่ไหม

ถ้า Apps Script มีการ validate `seats <= 2` อยู่ ต้องปลดเป็น 10

## 5. หลังบ้าน (Custom invite)

ลิงก์เชิญต้องพาจำนวนที่นั่งไปด้วย อย่างใดอย่างหนึ่ง

- `?c=SL-XXXX` → `/api/ginfo?c=` ต้องตอบ `seats` กลับมา *(ทำงานอยู่แล้ว)*
- `?n=10` → แบบยาว ใช้เมื่อไม่อยากพึ่ง ginfo

ถ้าไม่ส่งทั้งสองอย่าง แขกจะเลือกได้ถึง `CFG.maxSeats` (ตอนนี้ 10) — ไม่ถูกจำกัดรายคน
